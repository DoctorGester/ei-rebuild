# ---- section combat_more
# Combat, second part (src/game/combat/combat_actions.cpp): the end of an attack order (FinishAction,
# DeliverAttack), bow missiles, item spell triggers, damage reactions and death (OnDamaged,
# HitDirection, PropagateHostility, WitnessMurder, SetDead: "Unit 12 damaged to death"), and
# healing (Heal: "Unit 12 was healed"). Combat log lines go to a console stream that is filtered
# out by default, so the filter is opened first. Each expect only looks at the output since the
# previous expect. The skill code (science / stealing, UseSkill) has no script command that
# reaches it; it runs only from the player's orders.
#
# The archer is the unit prototype "Human Gipath Brigand A1" from database.res: a level 1 bandit
# whose first weapon is "bone short bow.decayed bones", so its attacks go through the missile
# branch of DeliverAttack. WolfTutor dies to the first hit (as in combat.txt).
waitfor 15 IsGreater(HP(GetLeader()),0)
# The level intro keeps the hero blocked; unblock it instead of waiting.
console @BlockUnit(GetLeader(),0)

# A death: the hero kills a wolf.
console @AddUnitToServer("Wolf1","WolfTutor","Wolf1",Add(GetX(GetLeader()),3),GetY(GetLeader()),0)
waitfor 10 IsAlive(GetObjectByName("Wolf1"))
console @SetPlayer(GetObjectByName("Wolf1"),6)
check IsEnemy(GetObjectByName("Wolf1"),0)
console @Attack(GetLeader(),GetObjectByName("Wolf1"))
waitfor 20 Not(IsAlive(GetObjectByName("Wolf1")))
expect damaged to death
check IsAlive(GetLeader())

# A second enemy attacks the hero until the hero is hurt. (The planned archer, "Human Gipath
# Brigand A1", neither attacked nor died within 20 s on the original game either, so a ranged
# attack is not covered yet; DeliverAttack's melee path is.)
console @AddUnitToServer("Archer1","WolfGreyF1","Archer1",Add(GetX(GetLeader()),3),GetY(GetLeader()),0)
waitfor 10 IsAlive(GetObjectByName("Archer1"))
console @SetPlayer(GetObjectByName("Archer1"),6)
check IsEnemy(GetObjectByName("Archer1"),0)
console #HP(GetLeader())
console @GSSetVar(0,"hp0",HP(GetLeader()))
# An order given right after the spawn is sometimes lost (about 1 run in 30 under 16 parallel
# games, on the original too): the attacker never swings. Give the new unit a moment, then
# repeat the order once; a repeated order on the same target only renews it.
wait 1000
console @Attack(GetObjectByName("Archer1"),GetLeader())
wait 1000
console @Attack(GetObjectByName("Archer1"),GetLeader())
waitfor 20 IsLess(HP(GetLeader()),GSGetVar(0,"hp0"))
expect was attacked by
console #HP(GetLeader())

# Healing: the healing spell reaches CUnitServer slot 21 (Heal), which logs it.
console @CastSpellUnit("healing{e2;e2;e2;e2}",GetX(GetLeader()),GetY(GetLeader()),GetLeader())
waitexpect 10 was healed
console #HP(GetLeader())

# The hero fights back until the archer is dead.
console @Attack(GetLeader(),GetObjectByName("Archer1"))
waitfor 20 Not(IsAlive(GetObjectByName("Archer1")))
expect damaged to death
check IsAlive(GetLeader())

# ---- section unit_ai_cast
# The AI casting (SV5's coverage list: CSpellEffect::UpdateMissile 00681BB0 was reached only by two
# scenarios without a golden). As in unit_ai_heal, one of zone1's own wolves (1804; units with script
# ids get no spell options) gets spells and an alarm of slot 0 rebuilds its options: a fireball (type
# 3, option kind 2: an area around the target) and a poison cloud (acid_fog, type 8, kind 3), with
# intelligence and the school's skill. The hero (in god mode) walks towards it and stops; the wolf
# casts the fireball at the hero twice, the second one catches the wolf too and it dies (the original
# does the same). Not reached yet: OrderCastAt 00554D00 (the wolf's casts are orders on the unit).
# No `speed`, so a golden can be recorded (standalone-verification.md, SV3).

console @GiveIntelligence(GetObject(1804),60)
console @GiveSkill(GetObject(1804),"elemental",5)

# ---- section unit_ai_heal
# The AI's heal option (UnitStats::ReduceKind1 00524020, which no other
# scenario reached). AIAttention::Build (005CEE80, from AIBrain::ApplyBehaviour 005D6630) turns a
# healing spell (type 0x18) into an option of kind 7; AIAttention::Choose (005D0030) scores every
# spell option on the unit itself and its allies in sight, and Score (005CF9A0) reduces a candidate's
# maximum hit points through ReduceKind1 for kind 7.
#
# Build gives units with script ids (1000000000 and up: AddUnitToServer) their weapon only, so the
# healer is one of zone1's own wolves (1804, which patrols towards the hero's start). GiveUnitSpell
# puts the spell into its slots; an alarm of slot 0 at the wolf (HearAlarm 005D5940 applies slot 0's
# behaviour whatever its record says) rebuilds its options. The hero (in god mode) then walks to it,
# and the wolf's target choice scores the heal on itself on every think. No `speed`: the virtual
# clock's default update length, so a golden can be recorded (standalone-verification.md, SV3).
# Back to the main menu for the next section.
frames 5
ifwindow battle key esc
waitwindow 10 escmenu
clickregion 3
frames 5
key enter
waitwindow 15 menu
newgame
waitfor 15 IsGreater(HP(GetLeader()),0)
waitfor 40 IsUnitBlocked(GetLeader())
console @BlockUnit(GetLeader(),0)
console @GodMode(0,1)
check IsAlive(GetObject(1804))
check IsEnemy(GetObject(1804),0)

console @GiveUnitSpell(GetObject(1804),"healing{e2;e2}")
console @InvokeAlarm(0,GetX(GetObject(1804)),GetY(GetObject(1804)))
frames 2
console @MoveToObject(GetLeader(),GetObject(1804))

# ---- section combat
# Combat: start a new game (hero on zone1) and fight two spawned enemies, exercising the rewritten
# CUnitServer combat code (combat.cpp): attack parameters, attack hit / damage roll, attack roll,
# hit resolution, TakeHit and its log ("Unit 12 was attacked by 34 skill=... damage=... destHL=Body",
# printed to the console, so the expects below see it), plus the range and weapon queries the AI
# uses on the way. Each "check" must print a nonzero value; each "waitfor" waits until its condition
# holds.
#
# WolfTutor dies to the first hit. GoblinF1 (database.res: a level 1 goblin, the same base values
# as WolfGreyF1, which has 25 where WolfTutor has 20 in its first stat field) is the sturdier enemy:
# it attacks the hero first until the hero is hurt, then the hero fights back. If the goblin turns
# out too strong for the starting hero, WolfGreyF1 is the next candidate; OgreTutor (80) is much
# stronger.
# Back to the main menu for the next section.

waitwindow 10 escmenu
clickregion 3

key enter

# The level intro keeps the hero blocked for ~37 s of real time; unblock it instead of waiting.

# A weak enemy: the hero attacks, one or two hits.
