# A merged run (H74): a quest script, the models drawn, the battle screen's spell book. Each section below was a scenario of its own that started the same way
# (section names as before: the notes name them); a section after the first starts again from the main menu with a new game.
# Sections: script_quest, models, ui_battle_spells.
# installs: vanilla
timeout 60
waitmenu
console thingamabob
newgame

# ---- section script_quest
# QFinish (004BAAB0, src/game/script/script_exec_helpers.cpp): QStart and three objectives (a string and a
# float argument, a float only, a string only), then QFinish builds the quest script text and loads
# it into the console's mission script. The verify wrapper compares ours' text with the original's
# (the original's load is skipped). The generated conditions name variables the mission may not
# have, so the load can fail quietly (QFinish prints nothing); the game must go on afterwards.
waitfor 15 IsGreater(HP(GetLeader()),0)
console @BlockUnit(GetLeader(),0)

console @QStart("zxq") QObjUse("zxLever",1.5) QObjGetItem(3) QObjKillUnit("zxUnit") QFinish() GSSetVar(0,"zxq.done",1)
waitfor 10 IsEqual(GSGetVar(0,"zxq.done"),1)
# A second quest with a single objective (the last objective's tail only).
console @QStart("zxr") QObjArea(7) QFinish() GSSetVar(0,"zxr.done",1)
waitfor 10 IsEqual(GSGetVar(0,"zxr.done"),1)
# QuestComplete looks the quest up in the quest table (004C9C90; an unknown name finds no record).
console @QuestComplete(0,"zxq") GSSetVar(0,"zxq.complete",1)
waitfor 10 IsEqual(GSGetVar(0,"zxq.complete"),1)
wait 500
check IsAlive(GetLeader())

# ---- section models
# Models and resources (src/game/model*.cpp). The databases (prints.db, acks.db: record and array
# serialisers) and the link loader's archives (figures.res, menus.res) load at startup; the new game
# loads zone1 and its figures (bounds, index buffers) and draws them (frustum clip test, viewport and
# projection matrices). Spawning units of several different prototypes loads more figures. Script
# SetWaterLevel drives the world's water level changes (TweenArray SetTarget / Tick, including the
# removal of a finished entry).
# Back to the main menu for the next section.
frames 5
ifwindow battle key esc
waitwindow 10 escmenu
clickregion 3
frames 5
key enter
waitwindow 15 menu
reject Script error
newgame
waitfor 15 IsGreater(HP(GetLeader()),0)
# The level intro keeps the hero blocked for ~37 s of real time; unblock it instead of waiting.
console @BlockUnit(GetLeader(),0)
console @GSSetVar(0,"hx",GetX(GetLeader()))
console @GSSetVar(0,"hy",GetY(GetLeader()))

# Different prototypes in a ring 8-12 units around the hero (each loads its own figure, textures
# and animations). They stay on their default (non-hostile) side.
console @AddUnitToServer("M1","BoarTutor","M1",Add(GSGetVar(0,"hx"),8),GSGetVar(0,"hy"),0)
console @AddUnitToServer("M2","ToadTutor","M2",Sub(GSGetVar(0,"hx"),8),GSGetVar(0,"hy"),0)
console @AddUnitToServer("M3","GoblinF1","M3",GSGetVar(0,"hx"),Add(GSGetVar(0,"hy"),8),0)
console @AddUnitToServer("M4","OgreTutor","M4",GSGetVar(0,"hx"),Sub(GSGetVar(0,"hy"),10),0)
console @AddUnitToServer("M5","BansheeTutor","M5",Add(GSGetVar(0,"hx"),9),Add(GSGetVar(0,"hy"),9),0)
console @AddUnitToServer("M6","SkeletonF2","M6",Sub(GSGetVar(0,"hx"),9),Add(GSGetVar(0,"hy"),9),0)
console @AddUnitToServer("M7","DeerF0","M7",Add(GSGetVar(0,"hx"),9),Sub(GSGetVar(0,"hy"),9),0)
console @AddUnitToServer("M8","SpiderF10","M8",Sub(GSGetVar(0,"hx"),9),Sub(GSGetVar(0,"hy"),9),0)
console @AddUnitToServer("M9","WolfGreyF1","M9",Add(GSGetVar(0,"hx"),12),GSGetVar(0,"hy"),0)
waitfor 10 IsAlive(GetObjectByName("M1"))
waitfor 10 IsAlive(GetObjectByName("M2"))
waitfor 10 IsAlive(GetObjectByName("M3"))
waitfor 10 IsAlive(GetObjectByName("M4"))
waitfor 10 IsAlive(GetObjectByName("M5"))
waitfor 10 IsAlive(GetObjectByName("M6"))
waitfor 10 IsAlive(GetObjectByName("M7"))
waitfor 10 IsAlive(GetObjectByName("M8"))
waitfor 10 IsAlive(GetObjectByName("M9"))
# Let them be drawn for a while (clip tests from several view directions as the camera follows).
console @MoveToPoint(GetLeader(),Add(GSGetVar(0,"hx"),4),Add(GSGetVar(0,"hy"),4))
wait 2000

# Water level 0: a new change towards 0 (the entry is removed once it has run its steps), then a
# second change to the same water while one is running.
console @SetWaterLevel(0,0,20)
wait 1000
console @SetWaterLevel(0,0,10)
console @SetWaterLevel(1,0,10)
wait 3000
check IsAlive(GetLeader())
# R16d: the image's frame with its figure meshes kept on the GPU must match the frame with every mesh
# built and uploaded again (scene_meshfresh), and no kept mesh checked against a fresh build may have
# been stale. (The original code captures the same frame twice.)
freeze
capture scene
meshcache off
capture scene_meshfresh
meshcache on
unfreeze
samecapture scene scene_meshfresh 8 0.001
meshcache check

# ---- section ui_battle_spells
# The battle screen's spell target modes (docs/notes/ui.md, "Battle screen"). The hero gets
# three spells (GiveUnitSpell) and a click on its portrait refreshes the spell column (00637DC0 ->
# 0063E820): the spells' buttons stand at x 760..800, the last one at y 470..510 and each earlier
# one 40 higher (0063E4B0), so with three spells their centres are (780, 410), (780, 450) and
# (780, 490). A click on a button (CHudSpellColumn::Click 0063EC90) starts its target mode
# (+0x17C: 1 for a spell with data flag 0x10000000, else 2) and "clickunit" on a wolf ends it
# through SelectUnit (00638EF0): mode 1 is the spell on a unit (00637500), mode 2 the spell at the
# unit's position (00637750). The wolves stand blocked next to the blocked hero; the report's call
# counts for CBattleScreenSetup::UseOnUnit / UseAtPoint show which were reached.
# Coordinates are the 800x600 layout.
# Back to the main menu for the next section.
frames 5
ifwindow battle key esc
waitwindow 10 escmenu
clickregion 3
frames 5
key enter
waitwindow 15 menu
newgame
waitfor 15 IsGreater(HP(GetLeader()),0)
console @BlockUnit(GetLeader(),1)
console @GodMode(0,1)
console @GSSetVar(0,"hx",GetX(GetLeader()))
console @GSSetVar(0,"hy",GetY(GetLeader()))
console @GiveUnitSpell(GetLeader(),"lightning")
console @GiveUnitSpell(GetLeader(),"firewall")
console @GiveUnitSpell(GetLeader(),"fireball")
waitwindow 15 battle

# The hero's portrait: selects it and shows its spells.
click 400 560
frames 3
check IsAlive(GetLeader())

# The action column (0..40 x 270..510; button i at y 470 - 40 i .. 510 - 40 i): with the hero
# selected, button 0 is "skill0011" (action -1: follow, mode 7) and button 1 the science button
# (action 0: mode 8). CHudActionColumn::Select (0063FB50): button 0, then button 1 (moves the
# highlight), then button 1 again (drops the pending action, so the spells below start clean).
click 20 490
wait 200
click 20 450
wait 200
click 20 450
wait 200

console @AddUnitToServer("SpellWolf1","WolfTutor","SpellWolf1",Add(GSGetVar(0,"hx"),3),GSGetVar(0,"hy"),0)
console @AddUnitToServer("SpellWolf2","WolfTutor","SpellWolf2",GSGetVar(0,"hx"),Add(GSGetVar(0,"hy"),3),0)
console @AddUnitToServer("SpellWolf3","WolfTutor","SpellWolf3",Sub(GSGetVar(0,"hx"),4),GSGetVar(0,"hy"),0)
waitfor 10 IsAlive(GetObjectByName("SpellWolf1"))
waitfor 10 IsAlive(GetObjectByName("SpellWolf2"))
waitfor 10 IsAlive(GetObjectByName("SpellWolf3"))
console @BlockUnit(GetObjectByName("SpellWolf1"),1)
console @BlockUnit(GetObjectByName("SpellWolf2"),1)
console @BlockUnit(GetObjectByName("SpellWolf3"),1)
waitunit 10 SpellWolf1
waitunit 10 SpellWolf2
waitunit 10 SpellWolf3

# Each spell's button, then a wolf.
click 780 410
wait 200
clickunit SpellWolf1
wait 500
click 780 450
wait 200
clickunit SpellWolf2
wait 500
click 780 490
wait 200
clickunit SpellWolf3
wait 1000
check IsAlive(GetLeader())

report
quit
