# The first frames after a scene is loaded (R56; docs/notes/renderer.md, "Frame capture"): nothing the renderer keeps
# (the shadow maps, the point shadows' faces, the terrain and mesh caches, the occlusion, the light) may start a frame
# late. Each load's first presented frames are captured one after another with the clocks frozen from the first
# ("capture <name> <count> freeze after|on ..."), then a frame later in the same frozen moment: the world view of the
# first frame must match it, and the second frame all of it. Outside the world view only the HUD moves on the
# second frame: the portrait's face eases into its selected turn and the clock's marks step, by the interface's frame
# time, which is 0 on the first frame after a load and then the load's. Loads: a new game, F8, the Load window, Esc >
# main menu > new game, the main menu's load of the quick save, a zone change (gz2g).
render checkall
timeout 120
reject Script error
waitmenu
console thingamabob
newgame
capture newgame 2 freeze after Saved savea
frames 10
capture newgame_later
unfreeze
samecapture newgame_1 newgame_later 8 0
samecapture newgame_2 newgame_later 8 0
waitfor 15 IsGreater(HP(GetLeader()),0)
waitfor 15 IsUnitBlocked(GetLeader())
console @BlockUnit(GetLeader(),0)
waitwindow 15 battle
move 400 20
frames 5
key f5
waitline 15 Saved saveq
frames 5

# F8: the quick save.

unfreeze
diffcapture quick_1 quick_later 0 0 8 60 280 900 600

frames 5
