# R9c3: the Scroll Lock screenshot and the frame recorder from the new renderer's frame
# (docs/notes/renderer.md, section 9). With "present" the render target and the primary are
# holders without a DirectDraw surface, and the surface capture (006D6D40, surface_capture.cpp)
# reads render::ReadFrame instead: the game's own file names (shot0000.bmp, in the saves overlay
# here), formats (a bottom-up .bmp in the screen's depth, 16 or 32 bits with channel masks) and
# moments (the key handler 005F78C0, the recorder after each present in 00458010).
#
# Scroll Lock (scan 0x46) is pressed at a frozen moment, once in the main menu and once in the game;
# the frame captured then must equal the file ("checkshot <n> <frame>": the file read back and
# compared as samecapture does; tolerance 8 covers the 5-6 bit channels of a 16-bit screen).
# The recorder (0079BC54, which nothing in the shipped game sets) is turned on by the harness for
# a few frozen frames; its first file (capture\shot0000.bmp: it writes under the movie folder, which
# defaults to .\capture\, and counts for itself) must match too ("checkshot recorder"), within 3%:
# a recorded frame lasts a fixed time (app_main.cpp), which overrides the freeze, so the client
# runs and what animates (water, the sea's edge) moves between "world" and the first file.
render new,present
reject Script error
waitmenu
console thingamabob

# The main menu.
move 400 20
wait 500
freeze
capture menu
key scrolllock
capture menu_after
checkshot 0 menu
unfreeze

# The game.
newgame
waitfor 15 IsGreater(HP(GetLeader()),0)
console @BlockUnit(GetLeader(),0)
waitwindow 10 battle
move 400 60
wait 1000
freeze
capture world
key scrolllock
capture world_after
checkshot 1 world
samecapture world world_after

# The recorder.
record on
capture recorded
record off
checkshot recorder 0 world 8 0.03
unfreeze
report
quit
