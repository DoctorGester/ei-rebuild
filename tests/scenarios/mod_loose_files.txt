# Loose files over archives (docs/notes/mods.md, "Loose files"): a mod of our own, tools/make_mod_s19d.py loose,
# written into the run's harness_saves\s19d_mod, which "mod" makes the settings' Mod (either install). At the main
# menu "modfile" and "modlist" open the game's archive as the game does and look a file up or list it:
# - texts.res: the mod's folder Res\texts\ comes first (s19d.txt: its 16 bytes, not the 7 of the mod's archive
#   s19d_texts_a.res), a sub-folder's file by its path in any case (Sub\S19D_Sub.TXT as sub\s19d_sub.txt); then the
#   mod's archive (s19d_c.txt, 21 bytes) with its own folder Res\s19d_texts_a\ over its entries (s19d_d.txt: 12
#   bytes, not 14); then the game's (map.txt). The listing: the mod folder's two names, the archive folder's one and
#   the archive's entries but s19d_d.txt (two): five.
# - outro.res: the mod's Res\outro\outro.rtf stands over the game's archive entry with no [RES] line; the game's
#   credits.scr still comes.
# - Maps: the mod's folder Maps\s19d_loose\ stands for s19d_loose.mpr (MapFileExists, as the client's shared-file
#   handler asks it), not for a .mob of that name.
# On an unpacked install (run_all.py --unpacked) the game's files come from its folders: the same answers.
# prepare: make_mod_s19d.py loose
# Only on Rebirth's data: the vanilla run checks nothing another scenario does not.
# installs: rebirth
mod harness_saves\s19d_mod
reject Script error
waitmenu
modfile texts.res s19d.txt 16
modfile texts.res sub\s19d_sub.txt 9
modfile texts.res s19d_c.txt 21
modfile texts.res s19d_d.txt 12
modfile texts.res map.txt +
modlist texts.res s19d* 5
modfile outro.res outro.rtf 15
modfile outro.res credits.scr +
mapfile exists s19d_loose.mpr yes
mapfile exists s19d_loose.mob no
mapfile exists s19d_none.mpr no
report
quit
