# Ticket queue

Generated from docs/tickets.toml and the statuses in the work database by tools/tickets.py: never edit this file; read one ticket with `python tools/tickets.py show ID` and change tickets through the script. The ticket board shows the same data.

- Workers own one ticket or area for about a usage session, commit small green groups (all checks green), and follow docs/worker-brief.md. The coordinator merges, runs the suite and keeps this file current.
- A ticket goes running when its worker runs `work.py start`, review when the worker's branch is ready, done when it is merged (`work.py done ID merged`); statuses live in the work database, so every checkout sees them at once.
- Mechanical tickets go to Sonnet; type recovery, renderer and tricky debugging to Opus. Sonnet tickets change spelling only, never a signature or grouping; the first diff of each kind is reviewed before more are sent.
