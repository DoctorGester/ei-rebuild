# Rebirth: what it patches, and its patches as flags in the rebuild

The Rebirth community edition (`F:\games\Evil Islands (Rebirth)`) runs the same game.exe 1.06 as the GOG install and changes it in
memory. This note says what each change does and how the rebuild reproduces it behind flags (`include/ei/rebirth.h`). The site-by-site
list (original instruction, summary, our status and where it is implemented) is `config/rebirth_patches.csv`, generated by
`tools/rebirth/make_csv.py` from `addon_sites.tsv` (the sites addon.log names) and `site_instr.txt`; run it, then
`tools/gen_rebirth_sites.py` (`src/hook/rebirth_sites.inc`). `docs/rebirth-patched-functions.txt` lists every function Rebirth patches
before WinMain. Source of everything here: static analysis of `starter\addon.dll` (v0.12.4.2), `EI_Plugin.asi`, `starter\Engine\dinput.dll`
and the two mss32.dll versions, checked against `addon.log`.

## Summary

- **addon.dll**: 52 patches in four tables (plus 35 mod-only ones needing a mod with an `[Addon]` section); here 34 are applied and 18
  logged as disabled. addon.log names 218 sites; three more are written without a log line (FixProcessLogin at 004433D6, FixRepairPrice's
  second site at 0060FB87, SetEiPluginMode at 0073AF10). A Rebirth launch writes `rebirth_unknown_diffs.txt` (any other changed range) and
  `rebirth_sites_live.txt` (each known site's bytes and where its CALL / JMP leads). By group (applied / all): bug fixes 10/10, widescreen /
  rendering 3/4, scripting / console 8/8, multiplayer 5/9, resources / paths 6/12, crash handling / infrastructure 2/9; 28 of the 34 change
  single-player behaviour.
- **EI_Plugin.asi** (multiplayer plugin) loads in Miles' `AIL_startup`, after WinMain, so its ~30 sites (NPlayers, Pause, NewMaster,
  Briefings, Fixes: all multiplayer) are not in the patched-functions list.
- The root-folder game.exe of the Rebirth install differs from `starter\Engine\game.exe` (the one we target) by two bytes: the Large-Address-Aware
  flag and the disabled CD check (00456BB5). 00443080 is FixProcessLogin (an unlogged JMP at 004433D6);
  005F7DA0 / 005F7E00 / 005F7E30 lie inside WideScreen #93 (194 bytes from 005F7D9E).

## How Rebirth gets into the process

`starter\Engine\dinput.dll` ("Addon Loader", a proxy) reads `HKCU\Software\Gipat.Ru\EI_Starter` (`path`, `Settings\AddonPath`), loads
`starter\addon.dll`, which writes a CALL at 006EC301 (the CRT's call of WinMain). Before WinMain addon makes .text / .rdata writable,
applies the patch tables and calls WinMain; `ei_hook.dll` installs its hooks when WinMain starts and so sees all of addon's patches.
WinMain creates the sound manager (006B6040), whose `AIL_startup` makes Miles load every `*.asi` in the working directory (mp3dec.asi,
EI_Plugin.asi); EI_Plugin writes CALL 10001BD0 at 006B6272 (right after `AIL_startup`), which applies its features and calls the original
006B73E0. The installer knows the plugin's sites and active features (from `EI_Plugin.ini` and the mode word) and keeps the original where
a hook would silently drop the plugin's change (0045C560 was one). dgVoodoo is the same in our vanilla runs.

addon reads `HKCU\Software\Gipat.Ru\EI_Starter\Settings` (`WideScreen`, `ObjectsDrawRadius` / `LandscapeDrawRadius` [100; 5376 here], `AddonPath` =
`starter\MODS\Standard`, ...), `...\General Settings\VIDEORESOLUTION`, `2utoexec.cfg` and the mod's `config.reg`. The Standard mod sets only title
and version, so the mod table does not run and mod-dependent patches are disabled except the resource redirections. `Settings\CtfMon`
(1 here) makes addon send WM_DESTROY to the text input service's window (`FindWindowA("CicLoaderWndClass")`, addon+FFB4) when it applies
its patches and, in its DLL_PROCESS_DETACH (addon+101CD -> addon+BCE5), start `<system32>\CTFMon.exe` with CreateProcessA and wait up to
2 s for it: under the loader lock, after every atexit function. Harness runs answer it 0 (S3e: it hung every Rebirth exit). EI_Plugin reads
`.\EI_Plugin.ini` `[CONFIG]` (NPlayers 7, Pause 1, NewMaster 1, Scripts 1, Briefings 1, Fixes 1; PK, AutoAim, GraphGen, Test 0).

addon's machinery: apply tables in a fixed order (the mod-dependent ones run only with a mod selected, "moved patches" only when a compatible
EI_Plugin.asi is found); apply functions return 0 applied / 1 disabled / 2 failed. Site kinds: *context hook* (the site's instructions, at
least 5 bytes, become a JMP to a stub that pushes the resume address, PUSHFD, PUSHAD and calls `handler(arg, context)`; the handler may
change registers and the resume address; mode 0 drops the replaced instructions, 1 runs them before the handler, 2 after), *function
replacement* (JMP to an adapter turning thiscall into an addon call, plus a trampoline), *call redirection*, plain JMP / CALL, raw bytes,
NOPs, data and import slots. Before writing addon compares the bytes with its own copy ("OrigChunk").

## The patches

*Implemented* = reproduced behind its flag (details: "Implemented patches: exact details"); where it lives is in the CSV. *Disabled here* = addon logs it as disabled in this install.

### Bug fixes (10 applied, single player; all implemented)

- **FixLeversActivate**: `LockKey::Opens` (00522A80) compares key and lock levels signed instead of unsigned, and for a level-0 lock returns
  the key's level + 1 (any key but level -1 opens it).
- **FixSpellEffectsOverflow**: (#1) `CMapObject::AddEffect` (0050F1E0, slot 45) refuses a 21st effect and, after adding an effect lasting more
  than one tick, removes every older effect of the same type and end flag whose +0x0C is within 0.001, that lasts no longer and whose value
  is not higher. (#0) a hook in `CWorldServer::UpdateUnits` (0058D670, at 0058D82E) counts every effect down one tick on objects that are
  asleep (+0x174 <= 0, out of the update map); one with an expired effect goes back into the update map (0058D5D0).
- **FixProgressNames**: the loading movie (00595080) picks progres2.bik for "gipat2", progres5.bik for "jigran".
- **FixSpellSelfCasting**: (#0) `CSpell::IsOffensive` (0068B770) also marks types 0x28 / 0x29 offensive; (#1) `CBattleScreen::SelectUnit`
  (00638EF0) always passes 0 as the flag to 00637500 when casting on a clicked unit.
- **FixMoveObject**: `CSectorMap::Move` (005C11D0) refuses x < 0, y < 0 or NaN (vanilla computes a negative sector).
- **FixAddMapObject**: object creation (005927C0): a unit with no prototype record is logged and uses index 0 instead of reading [0+8].
- **FixPlaingBattleMusicFromAntimagic**: `JMP +8` over the 0x1A test in 0054B580: antimagic no longer starts battle music.
- **FixRepairPrice**: the camp's price function (0060FAB0): the wear fraction 1 - durability / maximum is clamped to [0, 1] (negative or NaN
  as 0); taking an item apart in the item constructor (deal kind 7) adds the repair cost of its wear instead of subtracting.
- **FixRemoveMapObject**: `CWorldServer::RemoveObject` (005935C0): an unknown id is logged and the function returns (vanilla crashes).
- **FixCreateItem**: the item factory (006AC970): an unknown prototype or invalid prototype / material logs "GiveItem: ..." and returns no
  item instead of FatalError.

## EI_Plugin.asi

The plugin checks game.exe (PE header word at +0x150 is 0x2EC226), refuses when the mode word at 0073AF10 says so, makes the image
writable and patches 006B6272. Its first call reads `EI_Plugin.ini` and addon's mode word (0xAADDxxxx: bit 0 PK, 1 NPlayers = 6, 2 Pause,
3 AutoAim, 4 GraphGen, 5 Test, 6 NewMaster, 7 Scripts, 8 Briefings, 9 Fixes off). Active here (multiplayer): NPlayers (player count bytes

AutoAim, GraphGen, Test off. It updates itself from hat.gipath.org (a signed manifest, then a new EI_Plugin.asi), so its patch set may change.

S19a (installer at EI_Plugin.asi +0x28DD .. +0x29F9 and +0x2FD0):

## FPU precision

Measured (every scenario, both installs): the control word is 027F (53-bit) at WinMain and before `AIL_startup`, 007F (24-bit, round to
nearest, exceptions masked) from the first message-loop pass, i.e. after Direct3D (dgVoodoo) created the device, and it does not change
between frames; vanilla and Rebirth are the same. Statically nothing in Rebirth raises it: addon.dll and EI_Plugin.asi use a VS2010-2013
static CRT (`_cinit(0)`: only FNCLEX; every FLDCW is a save / restore inside a CRT maths routine; no `_controlfp` outside the CRT); the hook
handlers save only integer registers and flags; game.exe's own `_control87` calls (006C3A00, 006C8990, 006C9560) change the rounding mode
only and restore the whole word; mss32.dll calls `_controlfp` only at its own load (before Direct3D sets 24 bits). Other threads (Miles'
timer / mixer, the game's stream and MIDI threads, EI_Plugin's) start at 027F: game code running there (the sound manager's callbacks)
computes at 53 bits in both installs (Rebirth does not raise the precision). Every verify wrapper checks the control word when it reports:
a function seen at 53 or 64 bits is logged once ("FPU precision ... in <function> on the main / another thread; stack: ...", at most 30
lines) and listed in `harness_report.txt`. Returning ST0 results as `double` stays right either way.

## Flags in the rebuild

### The flags

`include/ei/rebirth.h` (header comment) documents the flags: one `ei::rebirth::Patch` enumerator per patch named as addon.log names it (52) plus one per EI_Plugin
feature, `ei::rebirth::Enabled(Patch::X)` in rewritten code, all off by default (with a flag off the code behaves exactly as the original, bugs included). Sources, in
order: `ei_rebirth.ini` next to ei_hook.dll, the `EI_REBIRTH` environment variable (`ei_launch --rebirth <spec>`, `harness.cmd ... --rebirth`), a scenario's `rebirthflags`
line; in a Rebirth launch with `FollowAddon=1` (the default) every flag then follows what addon.dll applied (any of its sites differs from game.exe on disk at WinMain;
import slots count only when they point into addon.dll) or EI_Plugin.asi will apply. The detection (`src/hook/rebirth_hook.cpp`) belongs to the hook DLL, the flags
(`src/lib/rebirth.cpp`) are plain data the standalone exe reuses.

### Installing and verifying flagged rewrites

A rewrite declares the patches it reproduces: `EI_REPLACE_METHOD(0x00522A80, LockKey::Opens);` then
`EI_REBIRTH_IMPLEMENTS(0x00522A80, ei::rebirth::Patch::FixLeversActivate);`. The installer decides per function:
- **Rebirth launch, function patched by addon.dll**: every differing byte must lie in a site of a patch the rewrite declares and that
  patch's flag must be on; then the function is hooked ("Rebirth-patched ... implements ...") and its verify wrapper compares ours, flag on,
  with the patched original; otherwise it is skipped with the reason.
- **Stolen bytes**: when an addon site lies in the wrapper's stolen bytes (addon's JMP at a function start: FixSpellSelfCasting #0,
  FixMoveObject, FixSpellEffectsOverflow #1, the WideScreen replacements) the stolen count must end at or after the site's end and the
  trampoline re-targets the copied JMP / CALL rel32 so calling it still runs addon's code.
- **EI_Plugin.asi** patches later: a function containing a site of an active plugin feature is not hooked unless the rewrite declares that
  feature and its flag is on.
- **Vanilla launch, flag on**: the original has no patched behaviour to compare with, so a comparing wrapper is not installed and the plain
  replacement runs ("UNVERIFIED ... the original does not have it"); wrappers that run ours only keep running. A Rebirth run is therefore
  needed only to verify a function whose rewrite reproduces a Rebirth patch: once when written or changed (then `verified.txt`), plus an
  occasional smoke run for a new addon / EI_Plugin version (`rebirth_flags.txt` runs the flagged functions). Functions Rebirth patches that
  our rewrite does not reproduce stay skipped.

### Implemented patches: exact details

Reproduced exactly: `FixLeversActivate` returns key level + 1 for a level-0 lock (addon's INC EAX); `IsOffensive` returns only AL; the
repair clamp stores the exact 1.0 / 0.0 and lets NaN through; `AddEffect`'s duplicate test uses addon's float / double comparisons (the
+0x0C difference rounded to float, its absolute value against the double 0.001) and steps past the record moved into a removed one's
place. Not reproduced: addon's log lines and the `FSTP ST(0)` its AddEffect wrapper executes on an empty FPU stack. Side-by-side against
the patched original in Rebirth: FixLeversActivate, FixSpellSelfCasting #0, FixPlaingBattleMusicFromAntimagic, FixRepairPrice,
FixProgressNames, FixSpellEffectsOverflow #1, ImproveConsole, AddNewScriptCommands (through the existing evaluator / parser wrappers;
CalcGroup's has 7 stolen bytes); the rest ours only with state checks.

### WideScreen

addon computes its layout once, when it applies its patches (before WinMain), from the starter's registry settings, not from the game's
screen: `Settings\WideScreen` (DWORD, 1 when absent) and `EvilIslands\General Settings\VIDEORESOLUTION` (`"%dx%d"`). For a mode that
passes its checks (at least 800x600, wider than 4:3) the 4:3 part `width43 = H * 800 / 600` keeps the 800x600 layout in the middle, the
margins `(W - width43) / 2` pixels on either side, `extra = ceil((float)(margin * 800.0 / width43))` layout units (at WinMain's 53-bit FPU
precision). It writes `800 + extra` to 00742B08 and `695 + extra` to 007428AC, scales layout to screen with the margin added and screen to
layout with it taken off, and moves x by a *panel offset* (addon's 100BD0A0: `-extra` or `+extra` while one of its panel builders runs,
0 otherwise) in `CUiRegion::SetRect` / `AddPoint` and the sprites' Place; the builders and other sites use the widths and the offset to put
the battle screen's panels at the screen's edges.

**Done (W1)**, `src/game/ui_widescreen.{h,cpp}` behind `Patch::WideScreen`: the layout from the same settings (read through the game's
own RegQueryValueExA import, so harness runs can answer them), the two widths written at hook time (an `EI_STARTUP_ACTION`, new in
`include/ei/hook.h`: runs after the Rebirth flags are known and before the hooks are installed), the scaling 005F7CA0 / 005F7D20 /
005F7DA0 / 005F7E00 / 005F7E30, SetRect / AddPoint (005FC9E0, 005FCA70) and `CUiMesh::PlaceBody` (005E6FA0). 005F7D60 is a dead copy
of 005F7D20 (not rewritten). Details:
- addon's scaling tests ECX and adds / takes off the margin only when it is nonzero; its entries 005F7D9E / 005F7DFE (in front of
  005F7DA0 / 005F7E00, written over with its 194-byte #93) clear ECX, and its code at 005FDE94 (in 005FDE20, the text surfaces' draw)
  calls 005F7CA0 with ECX 0. The five hooks are `__fastcall` entries (`ScaleRectToScreenEntry` etc., ui.h) that take ECX 0 as "no
  interface": the wide scaling without the margin (with the flag off ECX 0 never comes).
- In a Rebirth launch, the panel offset is addon's variable (set by its builders until W3 ported them): the startup finds addon's variable (the
  operand of `ADD ECX,[m32]` / `ADD EAX,[m32]` in addon's SetRect, the JMP target at 005FC9E0, inside addon.dll) and our SetRect /
  AddPoint / Place read that one.
- 005F7DA0 / 005F7E00 / 005F7E30 lie inside addon's #93 site, so their verify wrappers steal whole instructions of addon's code written
  there (`EI_REBIRTH_LIVE_STOLEN`, `include/ei/rebirth.h`; the installer waives "stolen bytes end inside the site" for them, and a JMP at a
  function start inside a larger site is re-targeted).
- Verified side by side with addon's code in a Rebirth launch (ui_widescreen): every scaling wrapper, SetRect / AddPoint, PlaceBody x / y /
