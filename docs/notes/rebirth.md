# Rebirth: its patches and how the rebuild carries them

The Rebirth community edition runs game.exe 1.06 and patches it in memory: `starter\addon.dll` (v0.12.4.2; 52 patches,
plus mod-only ones needing a mod with an `[Addon]` section) and the multiplayer plugin `EI_Plugin.asi`. The rebuild
folds the patches in as its own code, with no flag: a GOG install and a Rebirth install run the same code and only the
folder's data differs. The mod-folder patches apply whenever a mod is played; EI_Plugin's player count and pause mode
are the host's choices on the create-server screen, NewMaster's second master a value ("Settings" below); a fatal error
ends the game on every install ("Fatal errors" below). The site-by-site list
(original instruction, summary, our status and where it is implemented) is `config/rebirth_patches.csv`, generated by
`tools/rebirth/make_csv.py`; `config/rebirth_patched_functions.txt` lists every function Rebirth patches. Source of
everything here: static analysis of addon.dll, EI_Plugin.asi, the starter's dinput.dll proxy and addon.log.

## The patches

### Bug fixes (always on)

- **FixLeversActivate**: `LockKey::Opens` compares key and lock levels signed instead of unsigned, and for a level-0
  lock returns the key's level + 1 (any key but level -1 opens it).
- **FixSpellEffectsOverflow**: `MapObject::AddEffect`, after adding an effect lasting more than one tick, removes every
  older effect of the same type and end flag whose value field is within 0.001, that lasts no longer and whose value is
  not higher (the difference rounded to float, its absolute value against the double 0.001); `WorldServer::UpdateUnits`
  counts every effect down one tick on objects that are asleep, and one with an expired effect goes back into the update
  map. Ours has no cap of 20 effects (addon dropped a 21st; the network's limit is 255) and no skip of the record after
  each removal.
- **FixProgressNames**: the loading movie picks progres2.bik for "gipat2", progres5.bik for "jigran".
- **FixSpellSelfCasting**: Rick magic and curse magic (types 0x28 / 0x29) are offensive (their records' `offensive`,
  assets/spells/spells.sdb.toml); `BattleScreen::SelectUnit`
  always passes 0 as the flag when casting on a clicked unit.
- **FixMoveObject**: `SectorMap::Move` refuses x < 0, y < 0 or NaN.
- **FixAddMapObject**: a unit with no prototype record is logged and uses index 0.
- **FixPlaingBattleMusicFromAntimagic**: antimagic no longer starts battle music.
- **FixRepairPrice**: the camp's price: the wear fraction 1 - durability / maximum is clamped to [0, 1] (negative as 0,
  NaN through); taking an item apart adds the repair cost of its wear instead of subtracting.
- **FixRemoveMapObject**: `WorldServer::RemoveObject` logs an unknown id and returns (vanilla crashes).
- **FixCreateItem**: the item factory logs "GiveItem: ..." for an unknown prototype or material and returns no item
  instead of FatalError (the line in ei-rebuild.log). A unit record's carried item that gives none is not added (both
  games crashed on it in AddCarried: Lost in Astral over the game's zone17, mods.md).
- **FixProcessLogin** (multiplayer): the join's age field is cleared (ours always did).

### Widescreen and rendering

- **WideScreen**: no flag; the interface layout follows the window's shape ("WideScreen" below).
- **ObjectsDrawRadius** / **LandscapeDrawRadius**: the rebuilt code's own; the object pass and the terrain take every
  sector, the views' clip tests choose what is drawn.

### Scripting and console (always on)

- **AllowScriptArgsInLoops**: a For / ForIf body is parsed with the enclosing script's locals.
- **AllowScriptsInMainMenu**: the main menu zone runs its first command queue (one run of the zone's start block).
- **AddNewScriptCommands** (`script_addon.h` / `script_addon.cpp`): the command table extended with 69 commands
  (GiveUnitWeapon, Str*, Rand*, NearestUnit, GiveExp, GameOver, GetDexterity, ShowAllUnits, PauseGame, SetWeather,
  AddMobEx, IsFileExists, StartCameraSave ...); the parser gets the signature letters `?` (optional rest) and `+` (repeat
  the previous type) and a stricter keyword match ("Orc1" is an identifier); the evaluators look the id up before the
  game's switch (CalcFloat, CalcObject, CalcGroup, RunCommand, and CalcString, which the Lua bindings call for string
  arguments). Of its seven commands that share a game command's name, IsAlive, IsDead and ResetTarget stay the game's,
  and ConsoleString, Add, Mul and Random keep the game's argument counts. Kept from addon: `DistancePointPoint`'s
  signature has two floats but it reads four; `Random` with one argument declines; `And` / `Or` truncate; `Max` / `Min`
  let NaN through; `FloatToStr` cuts trailing zeros without looking at index 0 ("100" with 0 decimals gives "1");
  `StrMid` with a negative count leaves the result untouched; `Say` only talks in a network game; `GSListPlayerVars` and
  `GiveExp` do not check the player; the stat override of GiveUnitWeapon / Armor is refused for text-key ids;
  `ShowAllUnits(0)` / `PauseGame(0)` pass 1. `IsFileExists` looks in the mod folder; sin, cos, pow are the modern CRT's.
- **PersistentGlobalVars** (`persistent_globals.cpp`): `gvar.*` variables survive where the game empties a variable
  table (all multiplayer paths: the party outside a game, the client's update, the saved parties' list). addon copies
  them into an MSVC 2010 `std::unordered_map<std::string, float>` (FNV-1 over every (len / 10 + 1)-th character, 8
  buckets growing by 8 at a load factor above 1, nodes in one list with each bucket's range in it), lets the game clear
  the table, then sets them again in that list's order, which decides their order in the game's hash chains (and so in
  saves and listings): `AddonStringMap` reproduces that container's insert, find and rehash.
- **NewStringEvents**: "gameover" plays buttons\gameover.wav and shows a game over window with the event's title and
  text.
- **AddNewConsoleCommands** (`console_addon.cpp`): after the cheat word, help extensions, addon, execs (loads a script
  file into the world's first script and runs it), listgvar, drawall and nogui 0|1|2 (GUI and cursor shown / GUI hidden
  / both hidden).
- **ImproveConsole**: a line equal to the last history entry is not added again; Ctrl+A selects the line, Ctrl+C / Ctrl+X
  copy (cut) as Unicode text, Ctrl+V pastes the clipboard's first line over the selection.
- **AutoExec**: the three "exec autoexec.cfg" executions first execute every "Console AutoExec" settings line and every
  line of `2utoexec.cfg` (read once).

### Multiplayer

Always on: ExtendedServerName (the connect list's and the host screen's wider name fields and ellipsis), MPSpeedControl
(no speed keys in a network client), PlayerNumbers (a new player gets the highest number of the other players + 1, else
0), MQClient (`ClientSession::OnFileChunk` only collects the chunks: a client never writes a file the server sends; the
original's join and `WriteMapFile` are gone, and with them Maps' site 9). Not carried: SetDefaultRate, MPConsole, MpZone, ChatLog and the mod-only table (PerkLimit, ExpCalc, the Lua* rule
replacements, ...).

### Resources and paths

The five mod-folder patches (Maps, ResOverride, MoviesPatch, CameraPatch, StreamPatch) apply whenever a mod is played,
on either install (`src/game/mod_folders.{h,cpp}`, `modfolders::Active`); without a mod every site is the game's own:
- The mod: the settings file's `[game] Mod` (mods.md) + `\` (Rebirth's starter's own `AddonPath` is not read). Its
  `config.reg` (the game's registry format) section [RES]:
  for twelve archives (aiinfo, database, databaseLmp, gfx, materials, outro, redress, sfx, speech, texts, textsLmp,
  textures) a value (string or array) names mod archives (paths relative to the mod) that `MappedResource::GetFile` asks
  before the game's archive; a value starting with `-` makes the game's archive ignored. The key is the lower-case path
  the game opens. figures.res / menus.res values are also extra figure archives (before the game's), textures / redress
  / menus.res values extra texture archives (after the game's three). The mod archives open at the first OpenResource or
  MaterialManager::Create.
- GetFile: the mod's archives for this archive, then the archive unless ignored; a `t\` or `s\` name not found is tried
  once more without the prefix. Each archive's folder of loose files stands over it (mods.md, "Loose files": the mod's
  folder before its archives, the game's folder between them and the game's archive). ListFiles: the mod's listings and
  the archive's own are appended to the caller's array, which is not emptied first. Both also with a mod that has no [RES] (Rebirth's Standard), as addon does for every
  archive; without a mod GetFile and ListFiles are the game's (no retry, the array replaced).
  CloseFile of a file a mod archive gave goes back to that archive (`modfolders::ArchiveHolding`); addon left it
  loaded and the game's archive logged "File already closed".
- Maps: `<mod>\Maps<sub>\*.*` listed once; before each of the maps-folder uses (new zone map / mob, MapPath,
  WorldClient::LoadZone, the zone table's "*.mq", LoadZoneQuests, MapFileExists) the file's name selects
  the folder: the mod's when listed (any case; the zone table: the mod's top folder has a `.mq`), else the game's. The
  choice stays until the next site.
- CameraPatch (Camera::LoadPath), MoviesPatch (every movie open), StreamPatch (the music stream's path): the mod's
  `Camera\`, `Movies\` or `Stream\` file of that name when it exists.
- Check: `tests/scenarios/rebirth_mod_folders.txt` (S19b), with a mod `tools/make_test_mod.py` writes into the run's
  folder and the harness step `mod harness_saves\s19b_mod`; `rebirth_mod_stream_movies`, `rebirth_mod_archives`,
  `rebirth_mod_maps` and `rebirth_mod_zone_table` (S19d, mods from `tools/make_mod_s19d.py`: Stream, Movies, arrays and
  `-` entries, extra figure and texture archives, every Maps site). Each runs on both installs with the same results
  (the mod's saves in `harness_saves\<mod>`). Not reproduced: Rebirth's own override folders, the
  mod's [CONFIG] / [DEV] / SavesPath.
- NivalRegistry (the starter's registry root) is dropped: one settings file serves both installs (standalone.md,
  "Settings file").

### Fatal errors

Rebirth's DisableExitOnCrashReport made the original's FatalError (00480080) log its text and return, and kept the
client's session when CWorldClient::Segment (005641F0) met a failed connection; the game then went on past the error,
mostly into a null pointer. The flag is gone (C167): each of the original's FatalError sites (about 98) is one of the
kinds below, the same on every install. An old `[patches] DisableExitOnCrashReport` line is ignored (one log line).

- **Real errors** (`game::FatalExit`, src/lib/crt.h: logs "fatal: <text>", the error box, exit(-1); 78 calls in 42
  files). Carrying on has nothing to carry on with.
  - A required file missing or broken: a resource archive (resource.cpp: the file, its header, its table); the
    databases (items, spells, units, perks, levers, quests, terrain prints, acks); the zone's map, sectors and AI map
    (terrain_landscape, terrain_sector, ai_map_load, tileDesc.reg), its .mob (world_zone LoadMapObjects), the AI
    events, a figure's skeleton or link file, lightning.dat, menus.reg, the music registry, the text messages; the
    first map or a save's map (app StartFirstMap, world_save, world_client_maps).
  - A corrupt save (app/game_flow.cpp kCorruptSave; item.cpp / spell.cpp RequireEveryRecord, already exits) or a save that
    cannot be written (app/game_flow.cpp).
  - Broken internal state: no free object id (base_manager), a clone of a shared object (core_refcount), an item or
    spell the factory cannot make (item_manager, spell_manager: construct, rune, prototype, manager), no figure manager,
    no wounds texture, an unknown particle type, a null texture to draw, a script call of the wrong type or argument
    count (script_eval, script_vars, script_parse_load, script_addon, script_exec_run: the parser checked them), a
    picture of another format (surface), no human in the camp's party, a null interface screen, a font not made, a new
    hero's unknown prototype.
- **Recoverable data errors** (`game::Warning`: logs "warning: <text>" to ei-rebuild.log only, so console and goldens
  stay as they were; the safe local thing where it occurs):

  | Site | Error | The safe local thing |
  |---|---|---|
  | objects/map_object_manager.cpp GiveStartingEquipment | a map unit's prototype the units database lacks | the unit gets no starting equipment |
  | players/party.cpp AddMember | a script's unit (AddUnitToServer, AddUnitToParty) of a prototype the units database lacks (MOD11; the original read through the null record) | no record, no unit; the script goes on |
  | objects/map_object_manager.cpp GiveStartingEquipment | a weapon, armour or spell that cannot be made | that piece is left out |
  | spell_manager CreateSpellFromText | an unknown spell name | no spell |
  | texture.cpp LoadTexture | a texture file of no format the renderer takes | not loaded (as a missing texture) |
  | texture_load FindLayers | a layer texture of another size | that layer is left out |
  | ai_footprint | a footprint's body part the figure lacks | that part is skipped |
  | ui_scroll_text | an unknown escape in a text | the rest of the text is one token (Rebirth's) |
  | sound_music SetZoneMode | no music theme for an allod | the stream stops, the music state stays as it was |
  | unit_ai_modes | a patrol with no points | one point at the unit |
  | world_zone SetZoneExits | an exit's entrance number out of range | that exit is left out |
  | app/game_flow.cpp | a zone change to a zone map.txt lacks | the main menu (sessions closed) |
  | script_exec | KillScript from the WorldScript | the call is left out |
  | app/main_loop.cpp | a movie frame file that cannot be written | recording stops |

  Real data reaches one: units of prototypes Lost in Astral's database lacks, in its gz8g (the game's "zone8 ..."
  units: "zone8 Ogre", "zone8 Orc Fighter1 M", ...) and gz17g (a leftover map.txt zone no exit leads to: "SpiderF15",
  "HyenaF6", ...); `mod_lost_in_astral_gipat` enters both, `mod_lost_in_astral_unknown_prototype` checks the warning (and a script's AddUnitToServer of "WolfTutor").
  No other warning shows in the logs of the Rebirth set's 138 runs.
- **Network errors** end the connection, not the game: a message the player's state does not expect
  (`PlayerMessageError`, 8 calls: a warning, the handler returns 0 and the session closes) and a client's failed
  connection or unreadable packet (`CWorldClient::RunTick`, the original's Segment: a warning and SessionDisconnect).
  The original exited; Rebirth kept a dead session.
- **Dead checks** removed: the draw calls' and MappedResource::OpenResource's results (they never fail, or exit
  themselves), so SetTexture, DrawFigure, FigureMeshDrawer's draws, ReadImage, BeginConstruct, LoadPicture and the
  like return nothing.

### Dropped infrastructure

- GameExeDebug, BinkPatch, CommandLine, GraphGenPatches, SetEiPluginMode, DisableExitOnCrashReport ("Fatal errors"
  above) and EI_Plugin's loader entries.

## EI_Plugin.asi

The plugin's features (`EI_Plugin.ini [CONFIG]`): NewMaster, Briefings and Fixes are always on; NPlayers and Pause are
the host's choices on the create-server screen (C163; the ini is not read); PK, AutoAim, GraphGen, Test and Scripts are
not carried.
- **Pause** (`PlayerServer::OnPause`; the hosted game's `ServerSession::pauseMode`, `net::PauseMode`, chosen on the
  create-server screen: ui.md, "MpConnectScreen::CreateScreen"): Announced and AnyPlayer (the plugin's modes 1 and 2)
  announce pauses and resumes through the message keys "reserved_02" / "reserved_03"; AnyPlayer also replaces the leader
  test by the pausing player's own leader. Off (mode 3) skips the announcement and every pause of the server world (the
  plugin also dropped resumes, so a world paused before stayed paused; ours lets them through). Original (mode 0, the
  default) is the original's. Only a hosted game reads the mode (OnPause, World::SetServerPaused): single player
  always pauses (the plugin's
  mode 3 stopped that too). The key's digit is written on the host only (as the plugin did), so a joined game shows
  "reserved_02" for a resume as well; the host writes '2' before every announcement, so an Original game after an
  Announced one in the same run still says "paused".
- **Briefings** (always on; `WorldServer::CompleteBriefing`): a network client also queues the completion script
  (GSSetVar / #OnBriefingComplete) after asking the server.
- **NewMaster** (always on): the options do not save the Master Server Name; `ServerSession::OnMaster` takes answers from
  any address; `MasterLinkTick` leaves a master link that closed before anything arrived as it is. The second master
  server (`src/game/net/net_second_master.cpp`) is opt-in: `SecondMaster = host[:port]` in ei_settings.ini's `[network]`,
  empty by default and in harness runs. With an address: the main menu's Multiplayer click starts a look-up thread
  (gethostbyname, at most every 10 s) and waits up to 300 ms; each announcement goes again to it as the same bytes,
  EF BE AD DE, the number of bindings (a byte) and per binding the player's name as (strlen + 1 as a byte, the name, 0);
  `MpConnectScreen::MasterRequest` tries the parsed master with a nonblocking TCP connect (up to 1 s) and falls back to
  the looked-up address. Checked offline: `net_second_master` with a listener standing in for both masters.
- **Fixes** (always on; `pluginfixes`, src/game/players/faces.h): a face's sex is "f" when the model's fifth character is 'f', else
  "m" (`ModelIsFemale`; the multiplayer hero screen's figure loop: characters 4 and 5 "fe", `ModelNameIsFemale`); an
  unknown unit prototype falls back to the head of the first bucket of the prototype map whose name has none of "NPC",
  "Human", "Orc", "Undead", "Male", "Female" in it (`FallbackPrototype`); item damage lists always print "%.1f"; every
  unit's skins are refreshed, not only the hero's. Nothing in the shipped data reaches the fallback.
- **NPlayers**: the host's player slider runs to `net::kMostPlayers` (14: the chat strip's faces, 0x38 wide from x
  0x2E8 leftwards, fill the layout's width with 14) and starts at the original's 6. Each game lays its screens out for
  the session's limit, `ClientSession::PlayerLimit()`: the host's own (StartServer), a joiner's from the lobby's answer
  for the server it joined (ServerEntry::maxPlayers, set by the connect screen with the game type; the session's
  messages do not carry it), or the players present when more (the limit unknown). The HUD portraits' column is
  `count % max(limit, 6)`; for a limit above 6 the chat window's left edge is 0 (else 0x1D0) and its first status
  column 0x2E8 - the left edge. Above 7 the plugin's six extra sites of AddPortrait (00640060) apply as well: in a
  network client's row the faces are 20 wide at a pitch of 20 instead of 0x28 / 0x38 and 40 (`pitch`: the row's first x
  is `400 - (width + players * pitch - pitch) / 2` with the players present, the next faces' `x += width + column *
  pitch - pitch`), and every face model sits at depth 9.1875 instead of 7 (`crowded` in `HudPortraits::AddPortrait`;
  single player keeps 6 and 7). Scenario `net_pair_portraits` (the host drags the slider to 8; a pair: the captures
  `portraits_host` / `portraits_peer` show the narrow faces; a pair has two players, the wrap is not reached).

## FPU precision

The original game ran at 24-bit precision from the first message-loop pass (Direct3D set it), 53 bits before and on
other threads; Rebirth changed nothing there. The rebuild uses SSE2 floats throughout (float-maths.md).

## Settings

No patch has a flag; the one value that stays is the second master server: none by default; the settings file's
`[network]` `SecondMaster`, read by `src/game/net/net_second_master.cpp`; a scenario's `secondmaster` line stands over it.
The `[patches]` lines of older settings files (the flags of older builds, `NPlayers` and `Pause`,
DisableExitOnCrashReport) are not read: Rebirth's patches are always on, the players and the pause are chosen on the
create-server screen, a fatal error always ends the game. EI_Plugin's player count and pause mode are the host's choices when it creates a server ("EI_Plugin.asi"
above); EI_Plugin.ini is not read.

The kinds (the `standalone` column of the CSV):
- **always**: the bug fixes, the draw radii, FixProcessLogin, the scripting and console additions, the multiplayer ones
  (ExtendedServerName, PlayerNumbers, MPSpeedControl, MQClient) and EI_Plugin's NewMaster, Briefings and Fixes.
- **mod**: the five mod-folder patches, whenever a mod is played.
- **host**: EI_Plugin's NPlayers and Pause (the create-server screen's player slider and pause mode).
- **dropped**: Rebirth's infrastructure the rebuild replaces, DisableExitOnCrashReport and WideScreen (the layout
  follows the window).
- **none**: the mod config options, SetDefaultRate, MPConsole and EI_Plugin's inactive features.

Scenarios that show the fixes: `rebirth_fixes` (the same buff eight times keeps 4 effects on the hero where the
original kept 11), `rebirth_fixes_world` (FixCreateItem, FixMoveObject, FixRemoveMapObject), `rebirth_fixes_ui`
(FixLeversActivate, FixPlaingBattleMusicFromAntimagic, FixSpellSelfCasting #1). Not reached: FixSpellSelfCasting #0
(types 0x28 / 0x29 are not in vanilla spells.sdb), FixAddMapObject, FixRepairPrice, FixProgressNames, FixProcessLogin.
Rebirth's data runs the Rebirth set (`run_all --rebirth`; `config/rebirth_scenarios.csv`, every scenario with a step for one
install, plugin or widescreen, and every scenario with a Rebirth golden); `--all-rebirth` runs every scenario.

### WideScreen

addon computed its layout once from the starter's settings: for a mode at least 800x600 and wider than 4:3 the 4:3 part
`width43 = H * 800 / 600` keeps the 800x600 layout in the middle, the margins `(W - width43) / 2` pixels on either side,
`extra = ceil((float)(margin * 800.0 / width43))` layout units. It widened the layout widths 800 and 695 by `extra`,
scaled layout to screen with the margin added and screen to layout with it taken off, and moved x by a *panel offset*
(`-extra` or `+extra` while one of its panel builders runs, 0 otherwise) in `UiRegion::SetRect` / `AddPoint` and the
sprites' Place; the builders put the battle screen's panels at the screen's edges. The rebuild does all of it for every
window shape, in `screen_layout.{h,cpp}` (the module overview below) and, for the panel offset, as each edge panel's
origin (`UiWindow::originX`):
- Places scaled without the margin (addon's ECX 0): the text surfaces' draw, the edit field, the save / load list, the
  chat line, the tooltip (right edge at `800 + extra`, `LayoutRight`), the connect list; `screen_layout::ToScreenNoMargin`
  / `FromScreenNoMargin`.
- Text extent: pixels to layout units `w * 800 / width43`, `h * 600 / height` (`TextExtentToLayout`).
- Battle screen panels (the map, the unit panel, the weapon bar, the quick items, the spell and action columns, the
  movement panel, the clock; ui_hud_*.cpp) have their origin at `-EdgeShift()` (left edge) or `+EdgeShift()` (right
  edge) and add it to every x they give their regions, sprites and shapes, where addon's offset was set and where it
  moved their constants by hand. The ring (`UiMesh::Ring`) took no offset and takes no origin. The shape builders'
  coordinates are exact integers, so the origin added to each edge gives addon's sum (it added the offset twice to a
  rectangle's left + right); the movement panel's sectors, whose points are not whole, are shaped about the layout's
  corner and then placed at the origin (the same position SetTriangle would give).
  The weapon bar starts its regions at 80 - extra but still loops while x < 240 (at 3840x2160: eight regions, tips on
  the first four). The unit panel's draw puts the model at layout x 100 - extra - slide offset; the map's click takes the
  centre at 700 + extra.
- The axis swap's m[0] is `width43 / width` (`SceneView::axisScale`, set by screen_layout::Configure), so the 3D
  view at the full width keeps 4:3 proportions; the
  fonts' scale `width * 0.0075f / height` (the float 0.0075 widened to a double; `FontScale`); the backdrop at the
  window's size; the camera's and the global map's drags scaled without the margin (addon's read of the global map's pick picture at
  `x / 2 - margin / 2` went with the picture: the zone is found by its marker's faces at the mouse); curtains over the margins of the camp and the multiplayer hero screen
  (`AddCurtains`, `ShowHeroCurtains`: every mode but the hero list); the tutorial messages' frames moved to the edges
  (`TutorialFrameShift`: zt9:0, zt12:0, zt12:1, zt13:0, zt14:0, zt14:2, zt17:0, zt20:0, zt22:0 by `-extra`; zt3:2, zt4:0,
  zt4:1, zt7:0, zt10:0, zt10:1, zt18:0 by `+extra`).
- The connect list and host screen (ExtendedServerName next to WideScreen): rows to 278, the selection frame at 244.75,
  the ping column at 233; names drawn through a 90-byte copy with an ellipsis, the server's name clipped at 140, the
  details' name wrapped to 3 lines; the host screen's name field up to 50 characters.
- The widescreen scenarios (`ui_widescreen*`) compare frames with references (`run_all --widescreen`;
  standalone-verification.md, "WideScreen references"). A scenario with a `resolution` step runs alone on the machine.

## WideScreen module overview

The 800x600 interface layout is drawn in the window's 4:3 part, the largest 4:3 rectangle in the window, centred:
width43 = min(W, H * 800 / 600), height43 = min(H, W * 600 / 800). A window wider than 4:3 has margins left and right
of it (margin pixels each, `extra` layout units: addon's layout); a window narrower than 4:3 (5:4, portrait) has bands
above and below it (marginY pixels: the 4:3 part letterboxed, nothing moves into the bands, the 3D view keeps its
proportions over the whole window through the axis swap's y scale); at exactly 4:3 both are 0 and every value is the
original's. `screen_layout::Configure` computes them right after the options load, from the resolution the game loaded and makes
its window at, and again at each resolution change (`app::SetResolution`; renderer.md, "Resolution changes") (the
settings file's [video] VideoResolution; tests/scenarios/
ui_widescreen_resolution.txt; ui_layout_narrow at 1000x800).
- At 4:3 every branch's wide side gives the plain side's values (checked on every vanilla golden at 960x720). Two things
  are not addon's: the unit panel's setup keeps the original's slide and moves the original's rectangle by the shift,
  and the curtains are added at 4:3 too (empty sprites).
- The harness's runs follow the goldens' shape: vanilla 960x720, Rebirth 1280x720; vanilla scenarios at `resolution
  desktop` (16:9) get the wide layout.
